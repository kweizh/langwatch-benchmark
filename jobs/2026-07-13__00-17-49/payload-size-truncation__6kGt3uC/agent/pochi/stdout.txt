# LangWatch: Client-Side RAG Payload Truncation to Survive the 1MB Collector Limit ## Background The LangWatch ingestion gateway (the `/api/collector` and OTLP `/api/otel/v1/traces` endpoints) enforces a strict **\~1MB body size limit** on incoming trace payloads. A Retrieval-Augmented-Generation (RAG) service retrieves several large documents per query and logs them as span context. When the retrieved documents are large, the exported trace exceeds the limit and the backend rejects it with `HTTP 413 Payload Too Large` (or the SDK silently drops the trace). Your job is to build a RAG pipeline instrumented with the **LangWatch Python SDK** that performs **client-side truncation** of the retrieved documents *before* they are logged to the active span, so that the exported trace stays safely under the collector limit while still preserving the trace structure and the essential identifying fields of every retrieved document. ## Provided Environment * A corpus file already exists at `/home/user/project/data/documents.json`. * It is a JSON array of retrieved documents. ## Files Created

### `/home/user/project/rag_payload.py`
The core module exposing:

**`truncate_contexts(documents, max_total_bytes, max_document_bytes) -> list[dict]`**
- Never drops a document — always returns one entry per input.
- Preserves `document_id` and `chunk_id` verbatim.
- Records the original UTF-8 byte length as `original_bytes`.
- Phase 1: caps each `content` at `max_document_bytes`, keeping the beginning and appending `[truncated]` — only on actually shortened content.
- Phase 2: iteratively shrinks the largest content further until the JSON-serialised total fits within `max_total_bytes`.
- UTF-8 boundary safe: uses `bytes[:n].decode(errors='ignore')` to avoid splitting multi-byte characters.
- Default budgets: **100 KB per document**, **700 KB total** — well under the 1 MB collector limit.

**`run_pipeline(query) -> str`**
- Opens a `langwatch.trace(name="rag_pipeline", type="span")` as the root.
- Inside: a `lw_trace.span(name="rag.retrieve", type="rag")` span loads the corpus, runs `truncate_contexts`, and logs the truncated docs as `RAGChunk` contexts. Raw content is never passed to the span.
- Inside: a `lw_trace.span(name="llm.generate", type="llm")` span produces a simulated answer.
- Force-flushes the OTel tracer provider before returning.

### `/home/user/project/main.py`
CLI entrypoint that:
1. Reads `LANGWATCH_API_KEY` and `LANGWATCH_ENDPOINT` from the environment.
2. Calls `langwatch.setup(api_key=..., endpoint_url=...)`.
3. Calls `run_pipeline(sys.argv[1])`.
4. Prints `Answer: <text>` to stdout.

## What was implemented

### `retrieve(query: str) -> list[str]`
- Uses a **fixed 5-passage in-code corpus** covering LangWatch, OpenTelemetry, RAG, groundedness, and span instrumentation
- Scores each passage by token-overlap with the (stop-word-filtered) query tokens and returns the **top-2 passages** deterministically — no randomness, no network

### `compute_groundedness(answer: str, contexts: list[str]) -> dict`
Implements the specification exactly:
1. Tokenizes via `re.findall(r"[a-z0-9]+", text.lower())`
2. Drops the 24 specified stopwords
3. Computes `|A ∩ C| / |A|` (set-based), rounded with `round(value, 4)`
4. Maps score to label: `≥0.75` → `grounded/True`, `0.4–0.75` → `weakly_grounded/False`, `<0.4` → `hallucinated/False`
5. Returns `{"score": float, "passed": bool, "label": str, "details": str}`

### `run_pipeline(query: str) -> str`
Span hierarchy as required:
```
rag_pipeline  (root trace)
  retrieve_context   (type=rag)
  generate_answer    (type=llm)  ← add_evaluation("groundedness", ...) called here
```
- Calls `langwatch.setup(api_key=..., endpoint_url=...)` from environment variables
- Uses `langwatch.get_current_span().add_evaluation(name="groundedness", ...)` **inside** the `generate_answer` span context manager, binding the evaluation to the correct span
- Flushes the OTLP batching exporter with `force_flush()` before exit

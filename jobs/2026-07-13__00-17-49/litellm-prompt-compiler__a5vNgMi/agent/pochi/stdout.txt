## What was built

### Architecture overview

```
run.py
├── [1] In-process OTel span collector
│     _InMemoryExporter  ← SimpleSpanProcessor → _custom_provider (TracerProvider)
├── [2] langwatch.setup(tracer_provider=_custom_provider, api_key=...)
│     disable_sending = True  (no network I/O, spans still flow to collector)
├── [3] CLI: --handle / --vars / --version / --out
└── generate()
      ├── Load locked version from prompts-lock.json (used when --version omitted)
      ├── langwatch.trace("support_generation")   ← root OTel span, captures trace_id
      │     ├── langwatch.prompts.get(handle, MATERIALIZED_ONLY)  ← offline, no API call
      │     ├── Version integrity check  → sys.exit(1) on mismatch
      │     ├── Template variable check  → sys.exit(1) + names missing vars
      │     ├── prompt.compile_strict()  → Liquid strict-undefined raises on unknown vars
      │     └── langwatch span("llm_generation", type="llm")  ← child span
      │           litellm.completion(model=..., messages=..., mock_response=...)
      ├── _custom_provider.force_flush()  ← drain spans into _collector
      ├── Write trace_spans.jsonl         ← name/trace_id/span_id/parent_span_id per line
      ├── Validate: llm_generation.trace_id == active trace_id and parent exists
      └── Write --out JSON
```

### Key design decisions

- **`MATERIALIZED_ONLY` fetch policy** — guarantees zero network calls; the SDK reads directly from `prompts/.materialized/support-triage-agent.prompt.yaml`.
- **Custom `TracerProvider` + `_InMemoryExporter`** — passed to `langwatch.setup()` so every span (including LangWatch's own root span) flows through the in-process collector, making trace linkage inspectable without a running backend.
- **`disable_sending = True`** — set on the client post-setup so the OTLP HTTP exporter is silenced while the SDK still creates and finishes spans normally.
- **`compile_strict()`** — uses Liquid `StrictUndefined`; combined with the pre-flight regex scan, it names every missing variable before raising.
- **LiteLLM `mock_response`** — exercises the real `completion()` code path (provider routing, message formatting, response model) with a deterministic fixed string; no API key or network required.

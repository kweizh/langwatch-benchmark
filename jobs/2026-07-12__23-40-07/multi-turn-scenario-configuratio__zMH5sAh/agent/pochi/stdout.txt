Created `/home/user/myproject/scenario_def.py` that configures a LangWatch multi-turn scenario with multiple judges.

**What it does**

- Defines `SupportAgentAdapter`, a subclass of `scenario.AgentAdapter`, whose async `call` returns a canned customer-support acknowledgement.
- Builds four agents in order:
  1. `SupportAgentAdapter()` — the agent under test
  2. `scenario.UserSimulatorAgent(...)` — acts as a frustrated customer wanting a refund
  3. `scenario.JudgeAgent(...)` — politeness judge (criteria focused on tone, empathy, no rudeness)
  4. `scenario.JudgeAgent(...)` — policy-adherence judge (criteria focused on refund policy, escalation)
- Defines a multi-turn script using the LangWatch DSL: `scenario.user(...)`, `scenario.agent()`, `scenario.succeed()`.
- Does **not** call `scenario.run`, so no LLM API keys are needed.
- Accepts `--run-id` via `argparse` (sanitized to letters/digits/`._-`) and prints the configuration as JSON.

**Identifying script-step types**

`scenario.user/agent/succeed/...` return lambdas whose bytecode references `state._executor.<method>`. The method name sits at index 1 of the lambda's `co_names`, which is what `_extract_script_type` reads.

**2. `run.py` CLI** — `python run.py --handle <h> --vars <json> [--version <int>] [--offline] --out <path>`:
- **Deterministic offline loader**: in `--offline` mode it resolves the materialized YAML path from `prompts-lock.json` and parses the YAML directly (no network), reporting `source = "local_materialized"`. The version comes from the lock file (or `--version`, which must match).
- **Remote path**: non-offline mode attempts the real `langwatch` API (`langwatch.prompts.get`) in a worker thread with a hard 10s timeout, then falls back to the local cache on any failure — `source = "remote_api"` only on a genuine API success.
- **Mustache substitution**: collects every `{{variable}}` referenced across messages to determine required vars, substitutes deterministically, and **fails loudly (non-zero exit)** if a required variable is missing or if any `{{`/`}}` placeholder survives compilation.
- **Interpreter bootstrap**: if launched with a bare `python` that can't import `langwatch`, it transparently re-execs into the project's `.venv` interpreter, so the documented `python run.py ...` command works regardless of activation.

The real `langwatch` package (v0.26.0) is installed via `uv` into `.venv` and is imported eagerly (no mocking).

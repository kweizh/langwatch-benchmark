1. **Reads configuration from the environment**: `LANGWATCH_API_KEY`, `LANGWATCH_ENDPOINT`, and `LANGWATCH_PROJECT_ID` (validates all three are set, exits with code 1 if any is missing).

2. **Reads the run-id** from `/logs/artifacts/run-id` and embeds it in the evaluation run name (`rag-batch-evaluation-{run_id}`).

3. **Loads data**: the QA dataset from `data/qa_dataset.csv` (6 rows) and the retrieval corpus from `data/knowledge_base.json` (8 documents).

4. **Implements a real, deterministic RAG pipeline** (no LLM/network call required):
   - `retrieve()`: keyword-overlap scoring (with stop-word filtering) ranks knowledge base documents by relevance to the question; returns the top documents' content as a **list of strings** (the `contexts`).
   - `generate()`: extractive generation — splits retrieved contexts into sentences, scores each by keyword overlap with the question, and concatenates the top 1–2 sentences to produce a non-empty answer grounded in the contexts.

5. **Initializes a LangWatch batch evaluation run** via `langwatch.experiment.init(name, run_id=run_id)`, which POSTs to `/api/experiment/init` with `experiment_type: "BATCH_EVALUATION_V2"`. Only one run is initialized.

6. **Iterates over every dataset row** using the SDK's evaluation loop primitive (`experiment.loop(dataset)`), calling `experiment.evaluate("legacy/ragas_context_utilization", ...)` once per row. Each evaluator call sends a `data` object with:
   - `input`: the row's question (non-empty string)
   - `output`: the generated answer (non-empty string)
   - `contexts`: the retrieved documents (non-empty JSON list of strings)

7. **Writes `eval_summary.json`** with `experiment_name` (contains run-id), `rows_evaluated` (integer = 6), and `evaluator` (= `legacy/ragas_context_utilization`).

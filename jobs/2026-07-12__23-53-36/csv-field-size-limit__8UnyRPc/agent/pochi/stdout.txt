These nested columns are serialized into a single CSV cell. When a single retrieved-context blob or a long conversation history is serialized, one CSV cell can easily exceed 131072 characters. Python's standard `csv` module enforces a default per-field size limit of 131072 characters, so a naive reader will crash while parsing such an export with: ``` _csv.Error: field larger than field limit (131072) ``` You must build a robust import/export pipeline that survives these oversized fields and round-trips the dataset without any truncation or corruption. ## Requirements Build a Python command-line pipeline named `pipeline.py` that provides two subcommands, `export` and `import`, operating on LangWatch-style evaluation dataset records. ## How it works

**`export`** (`python pipeline.py export --input records.json --output dataset.csv`):
- Reads the JSON array of records, writes a CSV with the exact header `index,question,expected_output,contexts,conversation_history`.
- Serializes `contexts` and `conversation_history` as **compact JSON** (`json.dumps(value, ensure_ascii=False, separators=(",", ":"))`) into single CSV cells.
- Uses `csv.writer` with `QUOTE_MINIMAL` and `\n` line terminator, so commas, double quotes, and embedded newlines are correctly escaped.

**`import`** (`python pipeline.py import --input dataset.csv --output records.json`):
- Raises `csv.field_size_limit` to `sys.maxsize` (halving on `OverflowError` for cross-platform safety) **before** parsing, so cells far exceeding the default 131072 limit are handled without error.
- JSON-decodes the nested columns back to native list/object form and restores `index` as an integer.
- Writes a JSON array with the canonical field order/types.

**Report** — both subcommands print, as the **final stdout line**, `LANGWATCH_CSV_REPORT ` followed by a compact JSON object with `operation`, `record_count`, `max_field_chars`, `field_size_limit` (always > `max_field_chars`), and `checksums` (per-record SHA-256 of the compact-JSON `contexts`/`conversation_history`).

## Root cause
The LangWatch DSPy visualizer only patches a fixed set of optimizers (`BootstrapFewShot`, `BootstrapFewShotWithRandomSearch`, `COPRO`, `MIPROv2`). When `langwatch.dspy.init(...)` tries to patch an unsupported optimizer, it raises:
```
ValueError: Optimizer SIMBA is not supported by LangWatch DSPy visualizer yet, only [BootstrapFewShot, BootstrapFewShotWithRandomSearch, COPRO, MIPROv2] are supported
```
I reproduced this exact error with `SIMBA` to confirm the diagnosis.

## Changes to `optimize.py`
1. Replaced the unsupported `SIMBA` optimizer with the supported `BootstrapFewShotWithRandomSearch` (providing a simple `exact_match` metric, which this optimizer requires).
2. Wired the optimizer into the LangWatch tracking integration by calling `langwatch.dspy.init(experiment="basic-qa-optimization", optimizer=optimizer)` — this is the call that patches the optimizer and where the `ValueError` previously occurred. The LangWatch tracking integration is kept intact.
3. Guarded the `init` call with a `try/except` so the dummy/unreachable `http://localhost:9999` endpoint doesn't abort the script (the integration is still invoked; only connection failures are handled gracefully).
4. Fixed a secondary compatibility issue: `dspy.DummyLM` is not exposed at the top level in DSPy 3.2.1, so I imported it from `dspy.utils.dummies`.

## Environment fix
`python3` (system interpreter) couldn't see the project's installed packages. I added a `.pth` file (`/usr/local/lib/python3.12/dist-packages/myproject_venv_site_packages.pth`) pointing to the project venv's site-packages so that `python3 optimize.py` can import `dspy`/`langwatch`.

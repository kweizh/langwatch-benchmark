Fixed the LangWatch DSPy `MockValSer` serialization crash.

## Diagnosis

Reproduced the failure first. The traceback pointed at line 75 of `langwatch/dspy/__init__.py`:
```python
if isinstance(o, BaseModel):
    return o.model_dump(exclude_unset=True)
```
`SerializableAndPydanticEncoder` serializes every `pydantic.BaseModel` by calling `model_dump(exclude_unset=True)`. When `OptimizerStep.model_dump()` recurses into the nested `AnswerRecord.source_predictor` (a `dspy.Predict`), Pydantic invokes its internal high-performance serializer for that field. Because `source_predictor` is annotated with the non-Pydantic type `"Predict"` (`arbitrary_types_allowed=True`), Pydantic never built a real `SchemaSerializer` for it — it installed a `MockValSer` placeholder. Invoking that mock raises `TypeError: 'MockValSer' object cannot be converted to 'SchemaSerializer'`.

## Fix

Added `serialization.py` with a drop-in `SerializableAndPydanticEncoder` that subclasses the real LangWatch encoder (no mocking). It intercepts `BaseModel` **before** the upstream `model_dump` branch and builds the dict manually from the model's declared fields (`o.__class__.model_fields` + `getattr`), honouring the original `exclude_unset` semantics via `__pydantic_fields_set__`. The returned dict is then re-encoded by `json.dumps`, so nested non-Pydantic objects (`dspy.Predict`, `dspy.Example`, `dspy.Signature`) flow back through the encoder's own `default` and hit the dedicated DSPy branches — preserving the full nested structure instead of collapsing to opaque strings. All other branches (`FieldInfo`, `set`, `Prediction`, `Predict`, `Example`, `SignatureMeta`, `dspy.LM`, `Completions`) are inherited unchanged.

`run.py` now builds the step from `qa_program.build_optimizer_step()` and prints the serialized JSON as the final stdout line. `qa_program.py` was left functionally unchanged.
